## 2. Start, Stop, Continue

- **Start.** Додавати граничні випадки одночасно з новою логікою. Пошук варто одразу перевіряти з порожнім запитом, пробілами та іншим регістром. На початку наступного проєкту визначати незалежного рецензента й домовлятися про час перевірки.
- **Stop.** Залишати перевірку шляхів до публікації на кінець роботи. GitHub Pages відкриває PythonStart у підкаталозі, тому відносні адреси потрібні вже на першому етапі верстки. Припинити відкладати запис результатів до складання звіту.
- **Continue.** Працювати через окремі гілки, запускати `npm run ci:check` перед push, вносити відтворені дефекти в Issues та зберігати результати тестів поруч із рішенням. Продовжувати перевіряти зміни, запропоновані ШІ, за тестами й у браузері.

## 4. Індивідуальна рефлексія

У ролі Developer зібрав маршрут від вимог до релізної гілки. У ролі QA звірив поведінку тренажера з критеріями, оформив дефект і перевірив виправлення. Найбільше допоміг короткий сценарій відтворення. Його можна повторити після зміни й передати рецензенту разом із PR.
