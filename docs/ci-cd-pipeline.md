# Безперервна інтеграція PythonStart

## Запуск і перевірки

GitHub Actions запускає `PythonStart CI Pipeline` для pull request до `main` і до базової гілки ЛР 12 `fix/topics-safe-filter-and-stats`. Запуск на push у `main` перевіряє інтегрований стан. Push у `ci/13-github-actions-setup` забезпечує окремий результат для бейджа ЛР 13.

На `ubuntu-latest` конвеєр завантажує код, налаштовує Node.js 20.19.x, встановлює залежності командою `npm ci` та запускає `npm run lint` і `npm test`. Лінтер перевіряє обов’язкові файли, синтаксис JavaScript, маркери конфліктів і текстовий шаблон виклику `eval()`. Помилка повертає ненульовий код завершення. Локально обидві перевірки виконує `npm run ci:check`.

## Дії після помилки

1. Відкрити **Checks** у PR або потрібний запуск у **Actions**.
2. Розгорнути крок, що завершився помилкою, і прочитати повідомлення.
3. Виправити причину, запустити `npm run ci:check` і відправити новий коміт у ту саму гілку.
4. Перевірити, що запуск на новому коміті зелений. Попросити незалежне рев’ю перед злиттям.

Для `main` регламент вимагає Pull Request, одне незалежне схвалення та успішний **Linter & Unit Tests (Node.js 20)**. Базові гілки навчального стека залишаються окремими до інтеграції. Коли конвеєр буде в `main`, бейдж README можна перемкнути на запуски `main`.
