# Модульна архітектура PythonStart

## 1. Побудова застосунку

PythonStart поділено на модулі за принципом єдиної відповідальності. Навчальні дані можна доповнювати окремо від перевірки. Перевірка повертає результат і ключ повідомлення, а український текст за цим ключем дістає модуль локалізації.

Для ЛР 6 підготовлено дані й перевірку для тем «Змінні», «Умови» та «Цикли». У ЛР 7 зверстано інтерфейс за [прототипом Penpot](ui-ux-design.md). У ЛР 8 каталог і урок заповнюються з даних тем, а браузер зберігає прогрес. Списки заплановано для ЛР 10.

## 2. Призначення модулів

Робота індивідуальна. За модулі відповідає Паншин Артем у ролях Developer і QA.

| Файл | Відповідальність |
| --- | --- |
| data/topics.js | Масив topics із темами, теорією, завданням та еталонами. |
| js/messages.uk.js | Українські тексти каталогу, вправи й запуску. |
| js/i18n.js | Функція t(key) добирає повідомлення з українського словника. |
| js/validation.js | Функція validateExerciseAnswer порівнює відповіді й повертає статус, ознаку правильності та ключ повідомлення. |
| js/topics.js | Пошук тем і побудова карток, позначки виконаних тем. |
| js/workspace.js | Вміст уроку, події форми й керування підказкою. |
| js/storage.js | Читання, запис і скидання прогресу, нарахування балів. |
| js/app.js | Точка входу, перевірка відповіді, оновлення лічильника й повідомлень. |
| js/api.js | Паралельні GET-запити, перевірка JSON, обробка помилок і резервні поради. |
| js/apiWidget.js | Стан завантаження, виведення порад і повторення запиту. |
| tests/validation.test.js | Перевірки валідації, структури даних та ключів локалізації. |
| tests/storage.test.js | Перевірки збереження, відновлення, дублів і недоступного сховища. |

Шлях перевірки у вебінтерфейсі: еталон теми з data/topics.js → validateExerciseAnswer → t(messageKey) → текст у формі. Валідація обробляє порожній ввід першою, ігнорує крайові пробіли та горизонтальні пробіли в простих числових присвоєннях і викликах. Регістр, розриви рядків усередині відповіді та пробіли всередині числа залишаються значущими. Відповідь порівнюється як текст. Оцінка програм довільної форми виходить за межі цього модуля.

Запис `pythonstart_progress_v1` у localStorage містить `completedTopics`, `activeTopicId` і `totalScore`. Перший успіх у темі додає 10 балів. Під час читання вилучаються дублікати й невідомі ідентифікатори, а бал відновлюється за кількістю опрацьованих тем. Якщо запис недоступний, вправа працює зі станом поточної сторінки.

Локальна перевірка: `npm test`. Пакети встановлювати не потрібно, тести запускаються через Node.js.

Формат даних і поведінку віджета за помилок описано в [контракті даних](data-contract.md).

## 3. Робота з гілками і Pull Request

1. Взяти Issue в роботу й оновити локальну main командою `git pull --ff-only origin main`.
2. Створити `feature/номер-назва`, `fix/номер-назва` або `docs/номер-назва`.
3. Реалізувати завдання, виконати перевірки й зафіксувати зміни змістовним комітом.
4. Відправити гілку через `git push -u origin назва-гілки`, відкрити PR до main і вказати `Closes #номер`.
5. Переглянути diff і результати перевірок. Для злиття потрібне незалежне схвалення.
6. Після схвалення злити PR через GitHub, звірити статус Issue й оновити локальну main.

## 4. Алгоритм вирішення конфліктів злиття

1. Підтягнути актуальну main у робочу гілку. Якщо Git зупинив злиття, знайти незлиті файли через `git status`.
2. У VS Code зіставити поточний блок після `<<<<<<< HEAD` і вхідний блок після `=======`. Рядок `>>>>>>>` завершує конфлікт і вказує джерело вхідної зміни.
3. Узгодити остаточний вміст, прибрати маркери, перевірити diff та запустити тести.
4. Додати виправлений файл через `git add`, завершити злиття командою `git commit` і відправити робочу гілку на GitHub. За потреби скасувати незавершене злиття через `git merge --abort`.
